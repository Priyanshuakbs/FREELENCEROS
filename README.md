## ✨ Features

### 🏠 Dashboard & Analytics
- Real-time earnings overview with interactive charts (Recharts)
- Monthly revenue goal tracking with visual progress indicators
- Overdue invoice alerts and upcoming deadline summaries
- Recent activity feed across projects, clients, and invoices

### 👥 Client Management
- Full CRUD for client profiles (name, email, phone, company, address)
- Client-linked projects, invoices, and contracts in one unified view
- **Client Portal** — share a public, read-only project status page via unique token
- **Client Onboarding** — send token-based self-onboarding links to clients via email

### 📂 Project Management
- Create and manage projects with budget, deadlines, tags, and status
- **Kanban Board** — visual task management (`todo → in-progress → review → done`)
- Task priority levels (`low / medium / high`) with due dates
- File uploads per project (up to 10 MB via Multer + Cloudinary)
- Real-time team messaging per project (Socket.io)
- **Collaboration System** — invite collaborators by email with token-based accept/reject flow
- Public share token to expose a read-only client portal

### ⏱️ Time Tracker
- Start/stop timer for logging work hours against projects
- Manual time log entry with notes
- Aggregate total hours billed per project
- Generate invoices directly from time logs

### 🧾 Invoice Management
- Create itemized invoices with line-item tax (GST default 18%)
- Invoice lifecycle: `draft → sent → paid → overdue`
- **Automated Recurring Invoices** — weekly / monthly / quarterly cycles, auto-generated by cron job at midnight
- **Automated Overdue Detection** — daily cron at 9 AM marks past-due invoices as overdue
- PDF generation and download (Puppeteer headless browser — server-side rendering)
- Email payment reminders via Nodemailer (Gmail SMTP)
- **Razorpay Integration** — online payment collection with order creation and cryptographic payment verification

### 💸 Expense Tracking
- Log business expenses by category, amount, and date
- Filter expenses by project
- Expense summary for financial reporting

### 📄 Contracts
- Create and manage client contracts with status tracking
- Link contracts to specific projects and clients

### 📊 Tax Estimator
- Estimate quarterly and annual tax liability based on income and expenses
- Supports Indian freelance tax brackets

### 🤖 AI Assistant
- Integrated AI chatbot (Google Gemini API) for freelance business questions
- AI-powered proposal generation for new client pitches

## 🏗️ Architecture

FreelanceOS follows a **monorepo** structure with a clear client-server separation:

```
freelancer-saas/
├── backend/                # Express.js REST API + Socket.io server
│   ├── controllers/        # Business logic (one file per resource)
│   ├── models/             # Mongoose schemas
│   ├── routes/             # Express route definitions
│   ├── middleware/         # Auth guard, file upload, input validation
│   ├── utils/              # Email utility (Nodemailer wrapper)
│   └── server.js           # Entry point: Express + Socket.io + Cron
│
└── frontend/               # React SPA (Vite)
    └── src/
        ├── pages/          # Route-level page components (20 pages)
        ├── components/     # Reusable UI components
        ├── store/          # Zustand global state (auth)
        └── lib/            # Axios instance with auth interceptor
```

### Request Flow

```
Browser (React SPA)
      │
      │  HTTPS REST  /  WebSocket (Socket.io)
      ▼
Express Server (Node.js on Render)
      │
      ├── Middleware Chain:
      │     Helmet → CORS → Rate Limiter → Body Parser
      │     → MongoSanitize → JWT Auth Guard
      │
      ├── Route Handlers → Controllers → Mongoose → MongoDB Atlas
      │
      └── Socket.io (room-based real-time messaging & notifications)
```

### Authentication Flow

```
Register ──→ OTP Email Sent ──→ OTP Verified ──→ Login
                                                    │
                                                    └──→ JWT (30d) returned
                                                         Stored in Zustand store
                                                         Sent as: Authorization: Bearer <token>
```

### Route Guard Architecture (Frontend)

Three levels of protection implemented as React wrapper components:

| Guard | Condition | Redirect |
|---|---|---|
| `PrivateRoute` | Valid JWT + `isVerified === true` | → `/login` |
| `AdminRoute` | Valid JWT + verified + `role === 'admin'` | → `/dashboard` |
| `VerifyRoute` | Redirects verified users away from OTP page | → `/dashboard` |

## 🗄️ Database Schema

### User
```js
{
  name, email, password,        // password hashed via bcrypt pre-save hook (12 rounds)
  avatar, bio, title, company, phone, location,
  website, linkedin, github, portfolio,
  plan: 'free' | 'pro' | 'business',
  currency,
  role: 'admin' | 'user',       // admin = freelancer (owner), user = collaborator
  isVerified,
  verificationOTP, verificationOTPExpires,
  resetPasswordToken, resetPasswordExpire,
  monthlyGoal,                  // revenue target (default: 100,000)
  onboardingToken, onboardingTokenExpires
}
```

### Project
```js
{
  title, description, tags[],
  client:        ObjectId → Client,
  freelancer:    ObjectId → User,
  status: 'active' | 'completed' | 'on-hold',
  budget, deadline,
  tasks: [{                     // Embedded sub-documents
    title, completed,
    status: 'todo' | 'in-progress' | 'review' | 'done',
    priority: 'low' | 'medium' | 'high',
    dueDate, tags[]
  }],
  collaborators: [ObjectId → User],
  shareToken,                   // public read-only portal token
  files: [{ name, url, uploadedBy, size, createdAt }]
}
```

### Invoice
```js
{
  invoiceNumber,                // auto-generated: INV-YYYYMM-XXXX
  client:    ObjectId → Client,
  project:   ObjectId → Project,
  freelancer: ObjectId → User,
  items: [{ description, quantity, rate, amount }],
  subtotal, tax, total,
  status: 'draft' | 'sent' | 'paid' | 'overdue',
  dueDate, notes, paidAt,
  isRecurring,
  recurringCycle: 'weekly' | 'monthly' | 'quarterly',
  nextInvoiceDate,
  razorpayOrderId, razorpayPaymentId, paymentLink
}
```

## ⏰ Background Jobs (Cron)

Two automated jobs run daily, initialized after MongoDB connects in `server.js`:

| Job | Schedule | Behavior |
|---|---|---|
| **Recurring Invoice Generator** | `0 0 * * *` (midnight) | Finds invoices with `isRecurring: true` where `nextInvoiceDate ≤ now`. Clones each as a new `draft` invoice and advances `nextInvoiceDate` by the `recurringCycle` (weekly/monthly/quarterly). |
| **Overdue Invoice Checker** | `0 9 * * *` (9 AM) | Batch-updates all `sent` invoices where `dueDate < now` → sets status to `overdue`. |

## 🌐 Real-time Architecture (Socket.io)

The server uses **user-room** based WebSocket architecture for targeted event delivery:

```js
// Server — each authenticated user joins a private room keyed by their userId
io.on('connection', (socket) => {
  socket.on('join-room', (userId) => socket.join(userId));
});

// Emit targeted events to specific users from any controller
const io = req.app.get('io');
io.to(recipientId).emit('event-name', payload);
```

**Real-time events fired:**

| Event | Trigger | Recipients |
|---|---|---|
| `new-message` | Chat message sent in project | All project collaborators |
| `invite-received` | Collaborator invited to project | Invited user |
| `payment-confirmed` | Razorpay payment verified | Invoice owner (freelancer) |

## 🔒 Security

| Mechanism | Implementation | Details |
|---|---|---|
| **Authentication** | JWT | 30-day expiry, stateless Bearer token scheme |
| **Password Hashing** | bcryptjs | 12 salt rounds via Mongoose pre-save hook |
| **HTTP Security Headers** | Helmet.js | Sets CSP, XSS protection, HSTS, and more |
| **Rate Limiting** | express-rate-limit | 1,000 req/15 min (general); 60 req/15 min (auth routes) |
| **NoSQL Injection** | express-mongo-sanitize | Strips `$` and `.` operators from all request inputs |
| **CORS** | Custom origin validator | Whitelist: production domain + `localhost` in dev mode |
| **Email Verification** | OTP-based (6-digit, time-limited) | Required before accessing any protected feature |
| **Role-based Access** | `adminOnly` middleware | Returns `403 Forbidden` on unauthorized admin routes |
| **File Validation** | Multer config | 10 MB size limit with MIME type filtering |
| **Input Validation** | express-validator | Server-side validation on all mutation endpoints |
| **Payment Verification** | HMAC-SHA256 signature check | Razorpay callback signature verified before marking paid |

## 👥 Role System

| Role | Who | Access Level |
|---|---|---|
| **Admin** | Freelancer (project owner) | Full access: dashboard, clients, invoices, contracts, expenses, AI proposals, all project management |
| **User** | Collaborator / Invited member | Restricted: can view invited projects, manage tasks, send messages, upload files |

Access control is enforced at **two independent layers**:
1. **Frontend** — `AdminRoute` component wraps pages and redirects non-admins to dashboard
2. **Backend** — `adminOnly` Express middleware returns `403` for unauthorized requests, even if the frontend guard is bypassed

## 🚀 Getting Started

### Prerequisites

Ensure you have the following installed and accounts created:

- **Node.js** ≥ 18.x ([download](https://nodejs.org))
- **npm** ≥ 9.x (bundled with Node.js)
- **MongoDB Atlas** account — [Create free cluster](https://www.mongodb.com/cloud/atlas)
- **Gmail account** — with [App Password enabled](https://support.google.com/accounts/answer/185833) (not your regular password)
- **Cloudinary** account — [Sign up free](https://cloudinary.com)
- **Razorpay** account — [Sign up](https://razorpay.com) (use **Test Mode** for development)
- **Google AI Studio** API key — [Get key](https://aistudio.google.com/app/apikey) (Gemini features)
- **Brevo** account — recommended for production email delivery on Render

### 1. Clone the Repository

```bash
git clone https://github.com/yourusername/freelancer-saas.git
cd freelancer-saas
```

### 2. Backend Setup

```bash
cd backend
npm install

# Copy the environment template and fill in your credentials
cp .env.example .env

# Start the development server (nodemon watches for changes)
npm run dev
# ✅ Server starts at http://localhost:5000
```

### 3. Frontend Setup

```bash
cd ../frontend
npm install

# Set the API URL to point to your local backend
echo "VITE_API_URL=http://localhost:5000" > .env

# Start the Vite dev server
npm run dev
# ✅ App starts at http://localhost:5173
```

### 4. Verify Setup

Open in your browser:
- **Frontend:** `http://localhost:5173`
- **Health Check:** `http://localhost:5000/api/health` → should return `{ "status": "ok" }`

## 📦 Deployment

The project includes pre-configured deployment files for zero-effort hosting.

### Backend → Render

1. Push your repository to GitHub
2. Create a **Web Service** on [render.com](https://render.com)
3. Connect your repo — Render auto-detects `render.yaml`
4. Add all secret environment variables via the **Render Dashboard → Environment**

```yaml
# render.yaml (summary)
services:
  - type: web
    name: freelanceros-backend
    runtime: node
    rootDir: backend
    buildCommand: npm install
    startCommand: node server.js
```

### Frontend → Vercel

1. Import your repository on [vercel.com](https://vercel.com)
2. Set the **Root Directory** to `frontend`
3. Add environment variable: `VITE_API_URL` → your Render backend URL
4. `vercel.json` handles SPA routing by rewriting all paths to `/index.html`

```json
{
  "rewrites": [{ "source": "/(.*)", "destination": "/index.html" }]
}
```

## 🔧 Troubleshooting

### Common Issues

**Backend won't start — `MongooseServerSelectionError`**
- Verify `MONGO_URI` in `backend/.env` is correct and your IP is whitelisted in MongoDB Atlas → Network Access → add `0.0.0.0/0` for development

**Emails not sending — `Invalid login` error**
- Ensure you're using a **Gmail App Password**, not your actual Gmail password
- Enable 2FA on your Gmail account first, then generate an App Password from [Google Account Security](https://myaccount.google.com/security)

**Emails work locally but not on Render**
- Render Free blocks outbound SMTP ports `465` and `587`, so Gmail SMTP will fail there
- Use `BREVO_API_KEY` plus a verified `BREVO_SENDER_EMAIL` for production
- If you want Gmail SMTP in production, move to a host that allows outbound SMTP

**PDF generation fails — Puppeteer error on deployment**
- On Linux servers (like Render), Puppeteer may need additional Chrome dependencies
- Render's managed environment typically includes these; if deploying elsewhere, see [Puppeteer's troubleshooting guide](https://pptr.dev/troubleshooting)

**Vite dev server can't reach backend — CORS error**
- Confirm `FRONTEND_URL=http://localhost:5173` is set in `backend/.env`
- Confirm `VITE_API_URL=http://localhost:5000` is set in `frontend/.env`
- Ensure both servers are running simultaneously in separate terminals

**Razorpay payment not verifying**
- Use matching `RAZORPAY_KEY_ID` and `RAZORPAY_KEY_SECRET` (Test Mode keys start with `rzp_test_`)
- Payment verification uses HMAC-SHA256 — key mismatch will always fail silently
